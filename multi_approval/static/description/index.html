How It Works

The Four-Step Approval Pipeline

From initial configuration to final decision - every approval request follows a predictable, controlled, and auditable path.

1
CFG
Configure Type
Create an Approval Type: choose the target model (Sale, Purchase, Invoice...), define approval levels, assign signatories per level, set SLA hours, and activate email templates.
2
SUB
Submit Request
The originating user clicks "Request Approval" on the document. An Approval Request record is created and linked to the source document, which is locked from editing.
3
NTF
Sequential Approvers Notified
Level 1 approvers receive an email with a direct link. Once they approve, Level 2 is notified, and so on. Each level has its own SLA clock; overdue levels trigger escalation automatically.
4
END
Approved or Refused
When all levels are cleared, the document is automatically unlocked and can proceed. If refused at any level, the originator is notified with the reason and can revise and resubmit.
!
Fully Automated Workflow Engine
The entire pipeline runs automatically using Odoo's native mail, scheduled actions, and ORM hooks - no additional infrastructure or third-party integrations required.

Frequently Asked Questions

Everything you need to know before installing COA Multi-Level Approval Engine.

Q
Can I create approval types for custom models, not just Sales or Purchase?
Yes. The Approval Type configuration allows you to specify any Odoo model name in the res_model field. As long as the model exists in your Odoo instance, you can attach an approval workflow to it. This means you can extend approval to HR Leave requests, custom manufacturing orders, CRM leads, expense reports, or any other record type, including your own custom modules.
Q
What happens when an approver is unavailable or misses their SLA deadline?
The module uses a scheduled action (cron job) that runs at a configurable interval and checks for overdue approval lines. When a line exceeds its SLA deadline, an escalation email is automatically sent to the manager group or a fallback approver defined at the type level. Depending on your configuration, the system can either alert a higher authority while keeping the level pending, or auto-approve and advance to the next level to prevent deadlocks in time-critical workflows.
Q
Does the module conflict with Odoo's built-in purchase approval feature?
No. COA Multi-Level Approval Engine is designed to complement and extend Odoo's native single-level purchase approval, not replace its core workflow engine. For Purchase Orders, you have two options: disable the native single approver setting in Purchase settings and rely solely on the multi-level approval type, or use them in tandem where the native check acts as a prerequisite before the multi-level chain begins. The module's developers recommend the first approach for simplicity and a cleaner audit trail. Full guidance is included in the post-installation documentation.
